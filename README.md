# VBC Payer Command Center

A full-stack analytics platform for CMS Medicare Shared Savings Program (MSSP) contract
performance: a FastAPI backend serving precomputed ML pipeline output (PCA, KMeans, Isolation
Forest, composite scoring), and a React + TypeScript frontend covering portfolio-wide dashboards,
per-contract drill-down, and an LLM-grounded review brief.

This document is the exact, verified path to set the project up from scratch on a new machine —
every command below has been run and confirmed working, not copied from a plan.

---

## Project structure

```
project/
├── backend/app/
│   ├── api/            dashboard.py, acos.py, contracts.py, providers.py, hospitals.py,
│   │                    opportunities.py, review.py — FastAPI route handlers
│   ├── analytics/       financial.py, quality.py, utilization.py, peer_benchmark.py,
│   │                    contract_health.py — scoring logic (also directly runnable, see below)
│   └── services/        data_loader.py (loads all precomputed artifacts once, cached),
│                        llm_service.py (Review Brief narrative + grounding validators)
├── data/
│   ├── raw/              original CMS files, never modified, checked into this checkout
│   │   ├── mssp/          PY_Financial_and_Quality_Results...csv
│   │   ├── hvbp/           hvbp_safety__4_.csv
│   │   └── physician/      Medicare_Physician_Other_Practitioners...csv (real, national),
│   │                       physician_sample.csv (small synthetic file, same schema, for a fast run)
│   ├── processed/        gitignored — regenerated by the clean_*.py pipeline scripts
│   └── analytical/       gitignored — regenerated by the rest of the pipeline (scorecards,
│                          ML features, PCA, clusters, anomalies, drivers, opportunities, etc.)
├── pipelines/             runnable pipeline scripts — exact run order in Step 3 below
├── config/                driver_weights.yaml — composite score weights, never hardcoded
├── models/                joblib model artifacts, regenerated alongside data/analytical/
├── frontend/src/          React 19 + TypeScript app (Vite, Tailwind 4, Recharts)
├── tests/                 pytest suite — unit, API integration, ML regression, recommendation rules
├── notebooks/             analysis.ipynb — full analytical workflow with narration
└── report/                written_report.md + figures/ — project write-up
```

## Prerequisites

- **Python 3.13** (built and tested against 3.13.5)
- **Node.js 20+** and npm (tested with Node 22)
- The raw CMS files under `data/raw/` (already included in this checkout — nothing to download)

---

## 1. Get the code

Copy or clone the `project/` folder onto the new machine. Everything below is run from inside it.

## 2. Backend: virtual environment + dependencies

Create and activate a venv:

```powershell
# Windows (PowerShell)
python -m venv venv
venv\Scripts\activate
```

```bash
# macOS / Linux
python3 -m venv venv
source venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## 3. Configure environment variables (optional)

```bash
# Windows: copy .env.example .env
cp .env.example .env
```

Edit `.env` and set `ANTHROPIC_API_KEY` if you want the LLM-generated Review Brief narrative.
Leaving it blank is fine — the Review Brief falls back to structured-data-only display, and
everything else in the app is unaffected (this is the intended, tested degraded state, not an
error condition).

## 4. Generate the analytical data (required)

`data/processed/` and `data/analytical/` are gitignored — they don't exist on a fresh checkout and
must be built locally. Run these from the **project root**, with the venv active, **in this exact
order** (each step reads output written by an earlier one):

```bash
python pipelines/clean_mssp.py
python pipelines/clean_hvbp.py
python pipelines/build_scorecards.py
python pipelines/clean_physician.py data/raw/physician/Medicare_Physician_Other_Practitioners_by_Provider_and_Service_2024.csv
python pipelines/build_ml_features.py
python pipelines/pca.py
python pipelines/clustering.py
python pipelines/anomaly_detection.py
python pipelines/hospital_ml.py
python pipelines/provider_ml.py
python backend/app/analytics/contract_health.py
python pipelines/build_drivers.py
python pipelines/build_opportunities.py
python pipelines/build_recommendations.py
```

Notes:

- **`clean_physician.py` is the slow step** — the national file is 1.2M+ rows. For a quick local
  setup, point it at the bundled sample instead: `python pipelines/clean_physician.py data/raw/physician/physician_sample.csv`
  (the UI shows a "sample-scale demonstration" badge in this mode). To speed up the real file
  without switching to the sample, scope it to specific states: add `--states CA,NY,TX`.
- **`contract_health.py` lives under `backend/app/analytics/`, not `pipelines/`** — it's a backend
  module that's also directly runnable as a script. The path above is correct, not a typo.
- Every script prints a summary on completion; if one errors, fix that step before continuing —
  later steps will fail immediately with a missing-file error rather than silently using stale data.

## 5. Run the backend

```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

Verify it's up: `http://localhost:8000/api/health` should return `{"status": "ok"}`.

## 6. Run the frontend

In a second terminal, from the project root:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. Vite proxies `/api` requests to `http://localhost:8000` (see
`frontend/vite.config.ts`) — both servers need to be running.

Sign in with **any email and password** — the login screen is a client-side demo gate, not real
authentication; nothing is validated against a backend.

## 7. Run the tests (optional, but a good sanity check that the pipeline output is correct)

From the project root, with the venv active:

```bash
pytest tests/ -v
```

The full suite should pass with zero failures. If a test fails, it almost always means one of the
Step 4 pipeline scripts didn't complete successfully — re-run Step 4 in order before investigating
further.

## 8. Optional: the analysis notebook

```bash
jupyter notebook notebooks/analysis.ipynb
```

Requires Step 4 to have been run first (the notebook reads the same `data/analytical/` output).

## Troubleshooting

- **Frontend loads but shows "Could not load dashboard data"**: the backend isn't running, isn't
  on port 8000, or Step 4 wasn't completed — check the backend terminal for errors and confirm
  `http://localhost:8000/api/health` responds.
- **A pipeline script errors with a missing-file message**: run the Step 4 commands in the order
  listed — several scripts depend on output from earlier ones.
- **Port 5173 or 8000 already in use**: another process (often a previous unclosed `npm run dev` or
  `uvicorn`) is holding the port — stop it, or pass `--port` to run on a different one (update
  `frontend/vite.config.ts`'s proxy target to match if you change the backend's port).
